# V0 design: interactive AI presentation

> Historical record, superseded in part: models no longer run in the browser or download (live demos call Hugging Face through `/api`, Simulation replays recordings), the talk is hosted on Vercel with the local runtime as a development server, and there is one edition, `en`. Current state: [`docs/architecture.md`](../architecture.md).

Status: accepted for implementation, 2026-10-02.
Source of truth for product intent at the time: the original product brief (no longer in the repository; the talk today: [`docs/narrative.md`](../narrative.md)). This
document records the technical decisions taken to implement V0 and the contracts
that parallel workstreams code against.

## 1. Decisions on the plan's open questions (§17)

| Question | Decision | Why |
| --- | --- | --- |
| Framework | **Vite + React 19 + TypeScript**, pnpm workspaces, no SSR | Offline, local-first, served by our own runtime; SSR buys nothing. |
| Session transport | **Hybrid**: WebSocket relay in `apps/local-runtime` (LAN, phones), with **BroadcastChannel** fallback when no runtime is reachable (same-browser windows) | Phones need a server; a single laptop must still work without one. |
| Small causal model | **SmolLM2-135M** (base, `onnx-community/SmolLM2-135M-ONNX`) and **SmolLM2-135M-Instruct** (`HuggingFaceTB/SmolLM2-135M-Instruct`), 8-bit quantized ONNX, run in the browser with Transformers.js in a Web Worker (WebGPU when available, WASM otherwise) | Same size and tokenizer for base and instruct makes 3.6 a clean comparison; ~140 MB each runs on any laptop. OLMo-1B stays a documented optional presenter-machine upgrade, not V0. |
| Embeddings | **Precomputed** offline by a Node script with `Xenova/paraphrase-multilingual-MiniLM-L12-v2` (handles FR and EN), projected to 2D/3D in the script; **live** embedding of typed words in the browser with the same model, located by nearest neighbours | Deterministic layout, plus a genuine live interaction. |
| Audience phones | **Local LAN only** for V0, through the same runtime | No hosted infrastructure to maintain; the hosted relay can come later. |
| Edition inheritance | **Configuration**: an edition is a locale plus a cut (`full`/`short`) plus explicit include/exclude lists over one scene list | Enough for 45 and 75-90 minute paths; package composition can come in Phase 6. |
| Sources on projector vs handout | Projector shows **evidence badge + short source label**; Presenter View shows full source records and verification status; `/handout` lists everything | Keeps the projector clean, keeps evidence one glance away. |
| Licensing, gallery moderation | Out of V0 scope. Third-party artifacts carry their license in the manifest. | |

Additional decisions:

- **Languages.** Superseded by [`2026-10-03-locales.md`](2026-10-03-locales.md):
  the language is a launch parameter kept in the session, editions are cuts only.
  Every audience- or presenter-facing string is an `L10n` (`{ fr, en }`). Code, comments, docs, commit messages and the
  `claim`/`todo`/`localizationNotes` fields are English (repository rule).
- **One package for the canonical talk:** `presentations/canonical` holds scenes
  for all four editions (`fr-full`, `fr-short`, `en-full`, `en-short`), instead of
  the plan's `canonical-fr`/`canonical-en` folders, because translations live inside
  `L10n` values.
- **No Python backend in V0.** All local computation runs in the browser
  (Transformers.js/ONNX Runtime Web) or in Node scripts at preparation time.
  `apps/local-runtime` is a Node process that relays sessions and serves artifacts.

## 2. Repository layout

```
apps/presenter-web/        Vite app: every view (solo, projector, presenter, remote, join, prepare, overview, handout)
apps/local-runtime/        Node: HTTP + WebSocket on :4317. Session relay, artifact serving, prepare API, serves dist/ in production
packages/presentation-core/ Content model types, edition resolution, navigation (pure, tested)
packages/session-protocol/  Session state, commands, reducer, WebSocket + BroadcastChannel clients
packages/artifact-manager/  Manifest helpers; Node downloader/verifier (subpath ./node); browser readiness checks (./browser)
packages/ml-runtime/        Browser ML: Transformers.js setup for offline use, LM/tokenizer/embedder in a Web Worker
packages/scene-components/  Scene contract + registry, renderer, generic layouts, theme, interactive components by area
presentations/canonical/    The canonical talk: chapters, scenes/chXX.ts, editions, artifact manifest, bespoke data
content/                    @ai-exhibit/content: sources/ registry, assets/ (embeddings, recordings, traces, images)
scripts/prepare/            Artifact download/verify/purge CLI, embedding + recording builders
scripts/verify/             Content and source validators, rehearsal health check
docs/                       specs/, authoring/ guides, presenter guide
```

Packages export TypeScript source directly (`"exports": { ".": "./src/index.ts" }`);
Vite compiles them, `tsx` runs Node code. One root `tsconfig.json` typechecks
everything (`pnpm typecheck`); `pnpm test` runs Vitest.

## 3. Views and roles

All routes live in `apps/presenter-web`. Query parameters: `edition`, `token`, `s` (session).

| Route | Role | Purpose |
| --- | --- | --- |
| `/` | none | Launcher: choose edition, open views, readiness summary, QR for remote |
| `/present` | `solo` | Single window: projector + controller (rehearsal, one screen) |
| `/projector` | `projector` | Full screen, no chrome, display-only follower |
| `/presenter` | `presenter` | Current scene (live, controller), notes sidebar, next-scene preview, timer, chapter progress, sources, TODOs, scene controls, health, QR codes |
| `/remote` | `remote` | Phone: prev/next/reveal/reset/fallback/blackout, current talking point, next transition, timer, warnings |
| `/join` | `audience` | Phone: active poll only; otherwise "waiting" |
| `/prepare` | none | Readiness report, artifact download with progress, browser capability checks, model warm-up, smoke tests |
| `/overview` | none | Grid of every scene in the edition with metadata; rehearsal entry point |
| `/handout` | none | Public post-talk page: chapters, takeaways, all sources with evidence status |

**Scenes render on a fixed 1920x1080 logical stage**, CSS-scaled to fit the
viewport (letterboxed). Components size things in stage pixels and use the
tokens in `packages/scene-components/src/theme/tokens.css`.

**Compute ownership.** A scene component gets `ctx.role`:
`controller` (presenter or solo) accepts input, runs models/training and
publishes small results with `ctx.setState`; `display` (projector) renders
purely from `ctx.state`; `preview` (next-scene thumbnail) renders a static,
cheap version. A model never runs twice for one talk.

**Keyboard (presenter, solo):** `→`/`Space`/`PageDown` next step, `←`/`PageUp`
previous step, `Shift+→`/`Shift+←` next/previous scene, `F` toggle fallback for the
current scene, `R` reset scene state, `B` blackout, `Z` freeze projector,
`T` start/pause timer, `N` toggle notes, `G` go-to-scene palette, `Esc` close palettes.
Inputs inside interactive scenes must stop propagation of these keys while focused.

## 4. Session protocol

Contract: `packages/session-protocol/src/types.ts`.

- One session per runtime for V0 (`sessionId = "main"`).
- The runtime creates a random **presenter token** at startup (persisted in the
  cache dir so restarts keep paired phones). `GET /api/session/presenter-token`
  answers only to loopback requests. The presenter view shows a QR code
  `http://<lan-ip>:<port>/remote?token=...`; the projector or presenter can show the
  audience QR `http://<lan-ip>:<port>/join`.
- Controllers (`presenter`, `solo`, `remote` with valid token) may send every
  command except `vote`; `audience` may only send `vote`; `projector` sends nothing.
- `applyCommand(state, command): SessionState` is a pure reducer shared by
  clients (optimistic updates) and the relay (authoritative). Navigation targets are
  resolved client-side with `presentation-core` and sent as `goto`.
- Votes: one vote per `voterId` per poll (voterId is a random ID stored in the
  phone's localStorage); tallies only, no personal data. `history[pollId]` keeps
  results so chapter 11 can compare before/after.
- **Transport selection:** clients try `ws(s)://<host>/session` for 1.5 s; failing
  that they use BroadcastChannel `ai-exhibit:main`, where controllers are trusted
  (same browser profile) and the most recent controller answers snapshot requests.
- Dev: Vite on `:5173` proxies `/session` (ws), `/api`, `/artifacts` to the runtime
  on `:4317`. Production (`pnpm start`): the runtime serves `apps/presenter-web/dist`.
  Both bind `0.0.0.0` so phones on the LAN can connect.

## 5. Artifacts

Contract: `ArtifactSpec` in `packages/presentation-core/src/types.ts`; the
canonical manifest is `presentations/canonical/src/artifacts.ts`.

Logical IDs (stable, referenced by scenes):

| ID | What | Source |
| --- | --- | --- |
| `tokenizer-gpt2` | GPT-2 tokenizer files | `Xenova/gpt2` (tokenizer.json, tokenizer_config.json, config.json) |
| `smollm2-135m` | Base causal LM + tokenizer, 8-bit ONNX | `onnx-community/SmolLM2-135M-ONNX` |
| `smollm2-135m-instruct` | Instruct causal LM + tokenizer, 8-bit ONNX | `HuggingFaceTB/SmolLM2-135M-Instruct` |
| `minilm-multilingual` | Sentence embedding model, quantized ONNX | `Xenova/paraphrase-multilingual-MiniLM-L12-v2` |
| `embeddings-canonical` | Precomputed vocabulary vectors + 2D/3D coordinates | bundled, `content/assets/embeddings/` |
| `recordings-next-token` | Recorded top-k distributions for fallback | bundled, `content/assets/recordings/` |

Each Hugging Face artifact pins a **revision commit** and lists every file with
`size` and `sha256` (from the Hub tree API's LFS `oid`, or computed for small
non-LFS files).

**Cache:** `$AI_EXHIBIT_CACHE`, default `~/.cache/ai-exhibit`. Layout:
`artifacts/<id>/<revision>/<path>` plus `artifacts/<id>/<revision>/.verified.json`.
Shared across clones and editions; `pnpm artifacts:purge` removes it.

**Serving:** the runtime maps `GET /artifacts/<id>/<path>` to the manifest's
current revision in the cache (bundled artifacts map to `content/assets/...`).
Transformers.js is configured with `env.allowRemoteModels = false`,
`env.localModelPath = "/artifacts/"`, model ID = artifact ID, and ONNX Runtime
WASM binaries are served locally (copied from `node_modules` at build/dev time),
never from a CDN. **Nothing is fetched from the internet during a talk.**

**Prepare flow:** `pnpm artifacts:prepare [--edition fr-full] [--yes]` resolves
the artifacts used by the edition's scenes, prints sizes/licenses, asks before
downloading more than 50 MB (unless `--yes`), downloads with resume (HTTP Range,
`.part` files), verifies sha256, writes `.verified.json`, and prints a readiness
report. `/prepare` in the web app shows the same report from
`GET /api/artifacts/status`, can trigger `POST /api/artifacts/prepare` (progress via
SSE `GET /api/artifacts/progress`), then runs browser checks: WebGPU availability,
model load + warm-up, one smoke inference per runtime-B scene.

## 6. Scene content model

Contract: `SceneDefinition` in `packages/presentation-core/src/types.ts`.

- Scene IDs: `<chapter>-<kebab-slug>`, e.g. `03-probability-bars`. Numbers follow the plan (`"3.2"`).
- `visual.layout` is a generic layout (title, question, statement, cards, list, flow,
  compare, placeholder) or `component` with a registered name and props.
- Reveal steps: generic layouts reveal one item per step. Components declare how
  many steps they use through `scene.steps`.
- `optional: true` marks scenes the 45-minute cut drops. Full edition must sum to
  75-90 minutes, short to 40-50 (checked by `pnpm verify:content`).
- `todo` lists anything unverified. **Never invent incidents, numbers, quotes,
  company positions or regulatory details.** A claim without a verified source is
  either rephrased as a question/concept, or carries a `todo` and a source with
  `verification: "needs-verification"`.

## 7. Evidence and sources

Contract: `SourceRecord`. Registry: `content/sources/*.ts`, one file per area,
aggregated in `content/sources/index.ts`. Badges: `EvidenceBadge` (shape + text +
color; never color alone). Every risk/governance scene has `evidenceLevel` and at
least one `sourceId`, or a `todo` explaining what is missing.
`pnpm verify:sources` checks every URL (HEAD/GET with timeout) and reports dead links.

## 8. Reliability

- No scene blocks navigation: models load in a Worker, components show a loading
  state, and navigation never awaits them.
- Every runtime-B/C scene supports `mode: "fallback"` (recorded or deterministic data)
  and the `F` key switches in one keypress (< 2 s requirement).
- Artifacts missing → the component says so and offers its fallback automatically.
- `pnpm verify:content` validates the content model (fields, both locales, source
  and artifact references, component names, durations per edition).
- `pnpm rehearse` (Playwright) opens every scene of every edition in `/present`,
  with and without fallback, and fails on console errors or uncaught exceptions.

## 9. Visual direction

"Museum of AI" at night: near-black warm stage, ivory type, amber accent, teal
secondary. Display serif (Fraunces) for headings, Inter for body, JetBrains Mono
for tokens/IDs/numbers. Fonts bundled via `@fontsource` (offline). Minimal text
per projector scene; big type. Motion only where it explains; all animation
respects `prefers-reduced-motion` and the presenter's pause.
