# Locales: language as a launch parameter

Status: accepted for implementation, 2026-10-03.
Supersedes the "Languages" and "Edition inheritance" lines of
[`2026-10-02-v0-design.md`](2026-10-02-v0-design.md) §1.

## 1. Decisions

| Question | Decision |
| --- | --- |
| Where does the language live? | In the **session** (`SessionState.locale`), chosen at launch: `?lang=fr` on any view, or the language picker on the launcher. Presenter, projector, remote and audience views read it from the session, so they always agree. |
| What is an edition now? | A **cut only** (which scenes, how long). One edition, `full`, locale independent. `EditionDefinition.locale` is removed. |
| Old links | `?edition=en`, `fr`, `en-full`, `fr-short`... keep working: a leading locale code is read as `lang`, the rest as the edition (unknown rest: the default edition). |
| Single source of truth | `LOCALES` in `packages/presentation-core/src/locales.ts`, with `LOCALE_INFO` (native name, `Intl` tag) beside it. `Locale` and `L10n` are derived from it. |
| Which locales does the launcher offer? | `PresentationDefinition.locales` (canonical: `["en", "fr"]`), first one is the default. A locale in `LOCALES` but not there is a draft: it may be incomplete. |
| Reference and fallback | English (`REFERENCE_LOCALE`) is the reference: always present, and the meaning other locales follow. `L10n = { en: string } & Partial<Record<Locale, string>>`. Every read goes through `tr(value, locale)`: the requested locale, else English. No direct `value[locale]` indexing (a test scans the sources). |
| Where translations live | Slides are written once, in English, in the scene definitions and component copy. Each other language is one catalog, `presentations/canonical/locales/<lang>.json`: `{ key: { source, text } }`, keyed by scene ID and path for scene texts (`02-tokens/visual.props.items.3`) and by English text for component copy (`copy:Stop`). `pnpm locales:extract` adds new texts and never overwrites translations; `verify:content` reports missing, outdated (source no longer matches the English) and stale entries. An inline translation (`{ en, fr }`) still wins over the catalog, for the few texts that need a different translation in context. Per-language data (classifier datasets, embedding vocabulary, model family, scenarios, then-and-now questions) stays in code, one value per locale. |
| Typography | Applied at read time by `tr` from a per-locale rule table (`typeset`): French gets a narrow no-break space before `? ! ; %`, a no-break space before `:` and `»` and after `«`. Sources may use plain spaces; `verify:content` flags French strings with missing spaces or straight quotes. |
| Technical terms | Stay in English in every locale, followed on first or prominent use by the translation in italics: `deep learning (*apprentissage profond*)`. The markup is exactly `(*...*)`, rendered as italics by the shared `<Rich>` component (scene components, generic layouts) and by Markdown in speaker notes; `plainText()` strips it for attributes. The reference translations are `GlossaryEntry.translation` in the audience glossary; `verify:content` checks that content uses them. |
| Live examples | Each prompt, preset and example is an `L10n`, so the French talk sends French text to the models. |
| Recordings | Simulation replays real recordings per locale, keyed by locale and prompt. Missing French recordings are produced with the existing scripts (`record-cloud.ts`, `record-tokenizations.ts`). Historical outputs that cannot be re-recorded in French (GPT-2's answers) stay in English, with a French translation shown in italics and labelled as a translation. No output is ever written by hand. |
| Checks | `pnpm verify:content` reports, per locale, every missing scene string, text left identical to English, French typography and term glosses that differ from the glossary; plus missing per-locale recordings and translations of recorded English answers. It fails for an offered locale, warns for a draft locale. A render test and `pnpm rehearse --lang fr` fail on raw `(*` markup on screen. |
| Scope | Slide content only: what the audience sees, including live examples and their recordings. Presenter chrome (`?ui=`), speaker notes, the launcher and docs keep their existing language. |

## 2. Design

```
presentation-core/locales.ts   LOCALES, LOCALE_INFO, REFERENCE_LOCALE, Locale, L10n, Localized<T>,
                               tr(), pick(), own(), l(), parseLocale(), typeset(), plainText(),
                               installCatalogs(): tr/pick read the catalogs
presentation-core/catalog.ts   presentationTexts() (keys), registerPresentationTexts(), checkCatalog()
presentations/canonical/locales/<lang>.json + index.ts (generated): the catalogs
scripts/locales/              extract.ts (pnpm locales:extract), scan.ts (finds component copy)
presentation-core/types.ts     EditionDefinition (no locale), PresentationDefinition.locales
presentation-core/edition.ts   parseEditionParam(): legacy "fr-short" -> { edition, locale }
presentation-core/validate.ts  per-locale missing / identical / typography issues
session-protocol               setLocale { locale }: keeps scene and step, clears scene states
                               (they may hold text in the old language), keeps polls and timer
presenter-web                  useTalk: ?lang= applied once by controllers; launcher picker;
                               handout/overview/glossary ?lang=
scene-components               <Rich text> renders (*term*) in italics; components read ctx.locale
```

Recordings already carry a `locale` field; components look them up by
`(locale, prompt)`. The French tokenizer, base model and chat examples are the
French halves of the same `L10n` presets.

## 3. Migration

1. `editions.ts`: one edition `full`; `DEFAULT_EDITION = "full"`; legacy IDs
   parsed as above, so a relay that persisted `editionId: "en"` is moved to
   `full` by the first controller, keeping its locale.
2. Every `x[locale]` read becomes `tr(x, locale)`; the local `t`/`tr` helpers
   of scene components delegate to the core one.
3. Content: French reviewed against English, term markup applied, French
   typography normalized by `typeset`.
4. Catalogs: the reviewed inline French was moved into `locales/fr.json`
   mechanically, then removed from the sources; every French text the app
   shows was compared before and after (identical).
